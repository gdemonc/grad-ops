# Grad-Ops 威胁模型（Go + Linux）

> 本文是 Go + Linux 目标版本的安全基线。旧 Python 版的历史测试结果不能直接作为 Go 版安全保证。

## 1. 资产

- Linux 主机的可用性、服务状态、文件与日志；
- 运维人员身份、审批决策和授权凭证；
- 任务、提案、证据、执行记录、验证结果；
- LLM API 凭据、服务配置和数据库；
- 审计事件链及其验证结果。

## 2. 信任边界

1. 用户输入与外部日志均为不可信数据，可能包含提示注入文本。
2. LLM 输出是不可信提议，不是授权依据。
3. Linux 工具输出是观测数据，可能不完整、截断或受主机状态影响。
4. Policy、Executor 和 Approval 是安全关键模块，必须独立于 LLM。
5. 运行中的服务账号权限是系统安全边界的一部分。
6. 拥有 root、服务进程内存和数据库文件完全控制权的攻击者，可能同时破坏执行环境与本地审计；本地哈希链不能独自解决该问题。

## 3. 主要威胁与缓解

| 威胁 | 缓解要求 | 验收测试 |
|---|---|---|
| 提示注入诱导执行危险命令 | LLM 命令提案是不可信输入；调查仅允许 Policy 判定为 R0 的只读命令；副作用须经过 Action Contract 和审批 | 恶意日志要求删除文件或提权时，命令被拒绝 |
| 模型谎报低风险 | 风险由可执行文件、命令/参数语义、资源边界、身份和环境确定 | 将模型 risk 字段改成 R0 不影响实际风险判定 |
| 未知可执行文件或参数绕过策略 | 命令结构 schema、可执行能力规则和参数/资源约束；未知项 fail-closed | 未知二进制、畸形参数、额外字段和越界目标均被拒 |
| 动作契约篡改 | 规范化摘要绑定工具、参数、目标、策略版本和有效期 | 修改任一字段后执行拒绝 |
| 审批重放或并发双消费 | token hash、短 TTL、事务条件更新 | 并发提交同一凭证最多一次成功 |
| 路径穿越 | 资源根边界与实际文件对象校验 | `../`、绝对路径越界被拒 |
| 符号链接逃逸 | 采用 dirfd/openat 系列安全操作，拒绝不安全链接 | 链接指向边界外文件时无外部副作用 |
| TOCTOU 路径替换 | 在实际打开/操作时执行安全约束，避免检查后重用可变路径 | 在检查与执行间替换链接/目录的竞态测试 |
| Shell 会话越权或逃逸 | Shell Tool 使用专用非 root 身份和受控会话环境；Policy 约束操作权限，Runtime 在 OS 层限制资源、文件、网络和进程；特权操作经独立 broker | 尝试写入边界外路径、访问未授权网络、创建后台进程、调用 sudo 或耗尽资源时被阻断或终止 |
| Shell 动态语义无法静态判断 | AST 仅用于风险提示和审计；未知动态执行路径不能自动获得高权限，必须在受限 Runtime 内执行或转人工审批/拒绝 | 覆盖命令替换、动态命令名、外部脚本、eval、bash -c 和环境变量展开；验证运行边界仍然有效 |
| 工具输出耗尽内存 | 上限、超时、截断标志、结构化错误 | 超大 stdout/stderr 与超时测试 |
| 审批/数据库异常 | 事务边界明确，失败时不执行或记录不确定状态 | 注入数据库错误与并发锁争用 |
| Worker 崩溃后重复副作用 | 租约、执行阶段记录、幂等键/状态核对；不确定时暂停人工处置 | 执行后、写回前模拟崩溃 |
| 验证复用调查证据 | 验证器要求新的观测记录 | 传入调查 evidence ID 时验证失败 |
| 恢复失败被误报成功 | 单独记录恢复结果，失败进入 RECOVERY_FAILED | 恢复动作失败或恢复后检查不通过 |
| 审计链篡改 | 哈希链校验、序号与前驱校验；关键场景可外送签名检查点 | 修改/删除/重排事件可被检出 |
| 主机 root 或数据库管理员恶意篡改 | 文档声明本地保证边界；后续可将检查点外送独立存储 | 不声称仅靠本地链抵御完全控制主机的攻击者 |

## 4. 风险决策

- R0：只读观测，允许自动执行。
- R1：低风险、可逆变更；默认需要审批，只有明确配置且绑定具体工具/参数的策略才可免审批。
- R2：需人工审批。
- R3：高影响，默认拒绝或要求额外受限身份与二次确认。
- R4：禁止动作，不可通过普通审批放行。

风险等级不能由 LLM 自述决定。策略缺失、参数不完整、路径无法安全确认或授权状态不确定时，均拒绝副作用。

## 5. Linux 特定安全基线

- 服务默认非 root 运行。
- 支持 Agent 动态组合 Shell 命令与脚本，不要求将每种运维动作预先封装成固定工具；但不向模型暴露绕过策略和隔离的宿主机 Shell 权限、任意文件写入或任意 sudo。
- Shell Tool 提供真实 Bash 表达能力；不要求把每种运维动作预先封装成固定业务工具。
- AST 分析是辅助控制：用于识别命令结构、间接执行入口、潜在副作用并支持审批/审计；不能证明任意动态 Shell 安全，也不能作为唯一授权边界。
- Policy 根据用户/服务身份、目标资源、副作用、任务能力和部署策略做确定性授权。未知或无法判断的操作不得自动获得额外权限。
- Shell 应在专用非 root 身份和受限 Linux Runtime 中运行；通过 systemd/cgroup、文件系统保护、网络策略、超时和进程组回收限制影响范围。当前已实现可选的 uid/gid 切换、prlimit 资源上限、超时和进程组回收；systemd/cgroup、文件系统和网络边界仍未实现，因此相关威胁尚未被完全缓解。
- 高权限操作由独立、窄接口的 privileged broker/helper 执行；不允许 Agent 服务或 Bash Session 持有任意 sudo/root。
- 风险等级由确定性 Policy 根据实际命令语义、参数、资源范围、运行身份和环境计算；R0-R4 规则不能被 LLM 覆盖。
- 文件写操作必须处理符号链接、目录替换和 TOCTOU；单纯字符串前缀判断不够。
- 通过 systemd、文件权限和专用目录保护配置、数据库和凭据。
- 首期明确验证的发行版为 Ubuntu LTS；其他发行版的工具输出差异需要单独验证。

## 6. 残余风险

- 被控主机上的 root 攻击者可能篡改进程、文件、系统命令输出和本地审计。
- 观测结果可能因权限不足、日志轮转或系统瞬态状态而不完整。
- 人工审批可能发生误判。
- LLM 可能给出错误诊断，但其错误不应直接转化为未授权动作。
- 本地哈希链只能证明链内部一致性；若攻击者能重写全部事件和相关状态，需依靠独立存储或外部签名检查点提升保证。

## 7. 实现状态对照

上表的"缓解要求"是目标，不是现状。下面的状态按代码与其测试的实际内容填写；未实现的项在 `/api/safety` 中同样以 `warn` 出现，不会因为文档写了就变成绿色。

| 缓解要求 | 现状 |
| --- | --- |
| 提示输入不作为命令来源 | 部分：默认 `StubPlanner` 的探针是固定命令；`GRADOPS_PLANNER=model` 时任务文本只作为提示中的不可信数据，模型输出先经 schema/上限校验、探针只读分析和动作策略/审批。尚未做系统性的提示注入对抗测试 |
| 风险不由模型自报 | 已实现：契约不包含模型提供的风险字段，执行器用确定性 Policy 重算并比对 |
| 未知可执行文件、参数越界 | 部分：策略是正则匹配 + 路径词法规整，没有命令 schema 或可执行能力白名单 |
| 契约篡改 | 已实现：规范化摘要 + 执行前重算 |
| 审批重放、并发双消费 | 已实现：token 只存哈希、绑定摘要、单条 SQL 原子消费，并有并发用例 |
| 路径穿越 | 部分：只检查声明的路径是否落在允许根内，未解析真实文件对象 |
| 符号链接逃逸、TOCTOU | **未实现**：没有 dirfd/openat，也没有在打开时复核 |
| Shell 越权与逃逸 | **部分实现**：有进程组终止、超时、输出上限、调用预算、环境白名单、prlimit 资源限制，以及配置 `GRADOPS_EXECUTOR_USER` 后的 uid/gid 切换（非 root 无法切换时启动失败）；没有 namespace、cgroup、systemd 单元、文件系统或网络隔离 |
| Shell 动态语义 | 部分：`internal/command` 用 AST 识别写操作、间接执行和动态命令名，并用于探针、`observe` 动作和验证命令的 fail-closed 校验；未知命令和完整运行时语义仍无法证明，Policy 仍是正则匹配 |
| 输出耗尽 | 已实现：双流截断与标志位 |
| 审批/数据库异常 | 部分：单连接 SQLite 与事务边界已保证，锁争用与磁盘故障未注入测试 |
| Worker 崩溃后重复副作用 | 已实现：`UNKNOWN` 不重放、启动时恢复租约；崩溃点注入测试未做 |
| 验证复用调查证据 | 已实现：验证器重新观测，不复用调查记录 |
| LLM 密钥泄露 | 部分：客户端不在日志中输出密钥，错误只包含 HTTP 状态和截断后的 provider 文本；密钥仍由部署环境负责保护 |
| 未认证的 API 调用 | 部分：设置 `GRADOPS_API_TOKEN` 后所有 `/api` 路由要求 Bearer token；未设置时只允许回环监听，同机进程仍无认证，也没有用户/角色授权 |
| 恢复失败误报 | 已实现：`RECOVERY_FAILED` 与执行记录、审计事件 |
| 审计链篡改 | 已实现：修改、删除、重排均被检出；链尾截断在本机不可检测（已有用例说明） |
| root 或数据库管理员攻击者 | 不作为本地保证；需要外部检查点，未见实现 |

属性 → 测试的完整对照见 [测试矩阵与验证现状](testing.md)。
