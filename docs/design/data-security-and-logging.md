# 敏感数据与日志安全设计

> 状态：规划文档 / 首期安全要求
> 范围：单机部署、SQLite、Go 服务与 Linux 工具输出。

## 1. 目标

任务历史和审计需要足够的信息支持排障与追责，但不能因此无差别保存密码、Token、私钥或完整敏感配置。日志、任务历史、Evidence 和审计事件具有不同用途，应分别定义保留内容和访问边界。

## 2. 数据分类基线

至少识别以下数据：
- 认证凭据：密码、API Key、Bearer Token、Cookie、私钥。
- 主机与基础设施信息：IP、主机名、路径、服务名、端口、集群标识。
- 命令与工具数据：参数、标准输出、标准错误、退出状态。
- 任务与审计数据：请求内容、审批决定、操作者、时间戳、契约摘要。
- 模型交互数据：提示词、工具调用参数、模型响应和 Token 使用信息。

具体字段按实际工具和部署环境进一步分级；默认不把秘密值写入普通日志。

## 3. 脱敏与秘密处理

- 对已知凭据字段在写入日志、Evidence 摘要和前端展示前执行脱敏。
- 不记录审批原始 Token，只保存验证所需的哈希或不可逆摘要。
- API Key 等模型凭据从受保护配置或环境注入，不进入任务上下文。
- API Bearer token 从 `GRADOPS_API_TOKEN` 注入；请求日志不记录 `Authorization` 头。浏览器控制台把同一 token 放在 `localStorage`，不打包进前端产物。
- 工具输出可能包含秘密，不能仅依赖字段名过滤；应限制输出范围，并对已知格式执行二次扫描。
- 脱敏失败或数据格式无法识别时，敏感输出不得直接进入普通日志。
- 脱敏后的数据仍可能包含内部拓扑等敏感信息，应继续受访问控制和保留策略约束。

### 3.1 外部模型 Provider 的数据边界

`GRADOPS_PLANNER=model` 时，任务请求和被截断的探针观测会作为提示发送给配置的 OpenAI 兼容 provider。这是本机之外的信任边界：

- API Key 只从环境读取，进入 `Authorization` 头；不写入日志、数据库、任务上下文或 shell 环境。
- 客户端限制单次请求超时和响应体大小；模型响应按不可信输入处理，不能授权动作。
- 尚未实现提示内容的秘密扫描或自动脱敏。运维人员必须假定 provider 会看到探针输出，并在选择 provider、允许的探测命令和保留策略时考虑这一点。
- 默认 `GRADOPS_PLANNER=stub` 不向任何外部服务发送数据。

## 4. 日志、Evidence、History 与 Audit 的职责

- 运行日志：服务诊断信息，设置级别、轮转和大小限制；不承担完整业务记录。
- Evidence：当前任务观测结果，记录来源工具、时间、内容摘要和必要数据；原始内容按敏感级别控制保存。
- Task History：用于回看任务过程，优先保存结构化事件和引用，不复制不必要的大段原始输出。
- Audit：记录谁在何时对哪个资源做了什么决定或操作；与普通日志分离，保持追加式和链完整性校验。

四者不应互相替代，也不应为方便查询而重复保存全部敏感内容。

## 5. 输出与资源限制

所有工具必须设置超时、最大输出字节数和必要的行数限制。前端展示需进行安全转义，避免终端控制序列或 HTML 内容造成展示层风险。异常信息不得泄漏凭据、内部堆栈或不必要的主机敏感细节。

## 6. 保留、清理与备份

首期需要定义：
- 运行日志轮转与最大磁盘占用；
- Evidence 和任务历史的保留周期或手动清理策略；
- 审计记录的保留要求及清理权限；
- SQLite 数据库与备份文件的权限；
- 删除任务数据时如何处理审计关联和合规留存。

审计记录不应被普通任务清理流程静默删除。备份文件应视为与原数据库同等级别的敏感数据。

## 7. 首期验收

- 测试凭据不会出现在普通日志、错误响应和前端任务详情中。
- 工具输出大小限制与超时有效。
- 任务历史以结构化事件和引用为主，不无差别复制完整输出。
- 数据库、配置和备份文件使用最小文件权限。
- 日志轮转与磁盘占用上限有可复现测试。
- 审计事件与普通运行日志分离，审计完整性检查可运行。

## 8. 暂不纳入

首期不建设复杂数据分级平台、外部 SIEM 集成、集中式日志集群或多租户数据隔离系统。
