# 交接说明（2026-11-09，写给下一个在 Linux 上接手的人）

## 一句话现状

Grad-Ops 的 **Go + Linux 单机闭环**已实现并在一台 Windows 开发机（Git Bash 作 shell）上通过全部测试；Linux 专属能力（uid 切换、namespace、cgroup、systemd）**尚未实现，也没有在任何 Linux 机器上跑过**。下一步的工作环境是 Linux，这正好能补上"只在 Windows 验证"这个最大的短板。

## 代码地图

| 路径 | 职责 |
| --- | --- |
| `cmd/gradops/main.go` | 组装：配置 → 日志 → 迁移 → 租约恢复 → 各服务 → Worker 循环 → HTTP server → 优雅关闭 |
| `internal/config` | 环境变量读取与启动校验（非法值直接失败） |
| `internal/domain` | 任务状态机、R0–R4、时间格式、错误分类 |
| `internal/store` | SQLite（WAL、`busy_timeout`、`MaxOpenConns(1)`）、嵌入式迁移、`Tx` |
| `internal/audit` | 追加式 SHA-256 链 + 校验 |
| `internal/worker` | 认领、租约、重试、启动恢复、执行循环；**带副作用的作业不重放** |
| `internal/shell` | `Session`（每次调用一个 Bash）+ `Console`（常驻 Bash，跨调用保留状态） |
| `internal/policy` | 确定性 R0–R4 判定与审批要求；不导入 LLM |
| `internal/contract` | 规范化 JSON（排序键、无空白、拒绝浮点）+ 摘要；含 `compensation` |
| `internal/approval` | 一次性凭证：只存哈希、绑定契约摘要、单条 SQL 原子消费 |
| `internal/executor` | **唯一**副作用入口：重算摘要与风险、消费凭证、执行、记录；`Recover` 走补偿回滚 |
| `internal/verify` | 执行后的独立只读观测；失败且有补偿 → `ROLLING_BACK` |
| `internal/evidence` | 内容寻址证据（SHA-256）与引用校验 |
| `internal/investigation` | 探针 → 证据 → 结论必须引用证据 → 提案 |
| `internal/api` | REST：任务、证据、提案、审批、执行、验证、恢复、safety、审计校验 |
| `internal/e2e` | 全流程测试（真实组件） |
| `frontend/` | Vue 3 控制台，已对齐 Go 接口（`npm run build` 通过） |
| `scripts/demo.sh` / `demo.ps1` | 可复现冒烟：未到 `SEALED` 或审计链失败即非零退出 |

## 核心不变量（改动时必须守住）

1. **状态变更与审计事件在同一事务里**写入，否则重启后时间线与状态会对不上。
2. **API 不直接操作主机**，唯一入口是 `executor`。
3. **不确定的副作用绝不重放**：中断/超时记为 `UNKNOWN`，任务 `FAILED(outcome_unknown)`，等人确认。
4. **审批是绑定摘要的一次性能力**：token 只存哈希，消费与执行原子化；重放/换契约一律失败。
5. **策略不读模型自报风险**：执行前用 Policy 重算并与冻结值比对，不一致即拒绝。
6. **验证不复用调查证据**：`verify` 重新观测。
7. `MaxOpenConns(1)`：先把行读完再写库，别在 `Rows` 未关闭时开事务。

## 已知失败（不是代码 bug，是环境限制）

用真实进程开常驻探针模式：

```
err: run probe "uname -a": persistent shell is no longer running:
     the script ended the shell: 0 [main] bash (26208)
     ...\usr\bin\bash.exe: *** fatal error - couldn't create signal pipe, Win32 error 5
```

Git Bash 在没有控制台窗口的隐藏进程里创建 signal pipe 失败（Win32 error 5）。同一份代码在测试进程里正常，在 `Start-Process -WindowStyle Hidden` 的服务里失败。**这不是 Linux 问题**，但意味着"常驻会话模式"只有单元测试覆盖，没有真实二进制验证。到 Linux 上第一件事就是拿真实二进制跑一遍 `GRADOPS_PROBE_CONSOLE=true`。

默认关（`false`）的一次性 `Session` 路径不受影响，`scripts/demo.ps1` 一直能跑通。

## 验证过什么 / 没验证什么

**验证过（Windows 11 + Git Bash 3.5.7，Go 1.26.1）**

- `go test ./...`：15 包、126 个测试函数全绿（约 17 秒）
- `GOOS=linux go build ./... && go vet ./...`：0
- `scripts/demo.ps1`：建任务 → Worker 探针 → `SEALED` → 审计链 `ok`
- 一条 e2e：任务 → 证据 → 提案 → 审批 → 执行 → 验证 → 封存
- 前端 `npm run build`（含 `vue-tsc`）通过，dev 代理联调跑通过一次

**没验证 / 没实现（文档与 `/api/safety` 都标为未实现，别当成已完成）**

- Linux Runtime：非 root 专用身份、namespace、cgroup/systemd、文件与网络隔离；目前只有超时、输出上限、调用预算、进程组终止
- 符号链接与 TOCTOU：路径边界只做词法规整，没有 `dirfd/openat`
- AST 分析器、LLM 客户端（计划器是 `StubPlanner`，探针是固定命令）
- 提示注入、崩溃/磁盘故障注入、多进程并发测试
- Linux CI；`internal/shell/control_other.go` 是开发机存根，Linux CI 落地后应删除
- 真实 `/var/log` 路径语义、PGID 终止语义

## 到 Linux 后的第一步（建议顺序）

```bash
# 1. 环境
sudo apt-get install -y golang-go bash curl        # 或按 go.mod 版本装 1.26.1
go version && git log --oneline -n 3

# 2. 先确认基线（工作区里还有未提交改动）
GOCACHE=$PWD/.gocache go build ./... && GOCACHE=$PWD/.gocache go vet ./...
go test ./... -count=1                              # 这里 Bash 会自找到，无需 GRADOPS_TEST_BASH
GOOS=linux go test ./... -count=1                   # 可选：交叉平台覆盖

# 3. 真实二进制冒烟（两种 shell 模式都跑）
bash scripts/demo.sh 127.0.0.1:8080                 # 默认一次性 Session
GRADOPS_PROBE_CONSOLE=true bash scripts/demo.sh 127.0.0.1:8081   # 常驻 Console

# 4. 之前只在 Windows 跑过的 Linux 语义
#    - 进程组终止真的杀掉子进程吗（sleep & 后超时）
#    - /var/log 路径边界、run_as 校验在 Linux 上的用户名语义
#    - GRADOPS_REQUIRE_RUN_AS_MATCH=true 时是否按预期拒绝
```

然后按优先级：

1. 把上述未提交改动跑通、整理成一次提交（或直接改写）。
2. **Linux Runtime 隔离**：`internal/linux` 包（专用 uid、systemd transient unit 或 cgroup、资源上限），`/api/safety` 对应闸门从 `warn` 改 `ok` 只在真的生效后。
3. **symlink/TOCTOU**：策略层词法之外，在执行/打开时用 `dirfd/openat` 复核。
4. Linux CI（`go test`、`go vet`、交叉编译），删掉 `control_other.go`。
5. 之后再考虑 LLM 客户端与 AST（都不属于"单机闭环"必需项）。

## 开发环境坑（省得重踩）

- **PowerShell 改写含中文的文件会乱码**：`Get-Content -Raw` 按 ANSI 解码，写回就破坏 UTF-8。含中文的文件一律用编辑工具改，别用 `Set-Content` 覆盖。
- **Go 缓存目录**：沙箱下 `go build/test` 需要把 `GOCACHE` 指向工作区内（如 `$PWD/.gocache`），否则写 `%LOCALAPPDATA%` 被拒。Linux 上无此问题。
- **`-race` 在开发机不可用**（`exit status 0xc0000139`）；并发结论来自 `MaxOpenConns(1)` 与原子 SQL，不来自 race detector。
- **端口 8080 在这台机器上被系统保留**（`bind: access forbidden`），冒烟改用 18080+，Vite 代理可用 `GRADOPS_BACKEND` 覆盖。
- **`git push` 经常被重置**（`Recv failure: Connection was reset`），重试即可，别以为没推上去。
- Git Bash 会把 `/work` 这类环境变量自动转换成 Windows 路径，导致"必须是绝对 POSIX 路径"的校验失败——冒烟脚本因此显式不传这些变量。
- `scripts/demo.sh` 依赖 LF 换行（`.gitattributes` 已固定 `*.sh text eol=lf`）。
